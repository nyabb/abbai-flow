# Configuration

Configure the Docker server with environment variables, or use `VITE_*` variables for local development. Docker configuration is injected at runtime through `window.__ABBAI_FLOW_CONFIG__`; the Home Assistant token stays on the server.

## Docker environment variables

| Variable | Purpose | Default |
| --- | --- | --- |
| `HA_URL` | Home Assistant address used by the server proxy | `http://supervisor/core` |
| `HA_TOKEN` | Long-lived Home Assistant access token | unset; Home Assistant features are unavailable |
| `SUPERVISOR_TOKEN` | Legacy alias for `HA_TOKEN` | unset |
| `FAMILY_NAME` | Family name shown in the dashboard | `My Family` |
| `THEME` | Initial theme identifier | `skylight` |
| `WEATHER_ENTITY` | Home Assistant weather entity | `weather.home` |
| `PHOTO_DIRECTORY` | Photo directory path | `/media/beacon/photos` |
| `PHOTO_INTERVAL` | Seconds between photo changes | `30` |
| `SCREEN_SAVER_TIMEOUT` | Idle minutes before screen saver | `5` |
| `PORT` | HTTP server port | `3000` |
| `ABBAI_FLOW_DATA` | Directory for persisted server data | `/data` |

Example:

```yaml
services:
  abbai-flow:
    image: ghcr.io/nyabb/abbai-flow:latest
    ports: ['3000:3000']
    environment:
      HA_URL: http://homeassistant.local:8123
      HA_TOKEN: ${HA_TOKEN}
      FAMILY_NAME: Sachs Family
      THEME: midnight
      WEATHER_ENTITY: weather.home
    volumes:
      - abbai-flow-data:/data
```

The theme selector and other settings in the app can override these initial values.

## Development environment variables

Vite reads these from a `.env` file in the repository root:

| Variable | Purpose | Default |
| --- | --- | --- |
| `VITE_HA_URL` | Home Assistant address | empty |
| `VITE_HA_TOKEN` | Home Assistant token for local development | empty |
| `VITE_FAMILY_NAME` | Family name | `My Family` |
| `VITE_SAVE_CONFIG_IN_BROWSER` | Save configuration in browser storage | `true` |
| `VITE_THEME` | Initial theme identifier | `skylight` |
| `VITE_AUTO_DARK_MODE` | Enable automatic light/dark switching | `true` |
| `VITE_HA_WEATHER_ENTITY` | Weather entity ID | `weather.home` |
| `VITE_PHOTO_DIRECTORY` | Photo directory path | `/media/beacon/photos` |
| `VITE_PHOTO_INTERVAL` | Seconds between photo changes | `30` |
| `VITE_SCREEN_SAVER_TIMEOUT` | Idle minutes before screen saver | `5` |

The runtime config takes priority over Vite values, which take priority over application defaults. The version shown in About comes from the root `package.json` version and can be overridden at build time with `VITE_APP_VERSION`.

## Runtime configuration

The server serves `/runtime-config.js` before the application loads. It sets `window.__ABBAI_FLOW_CONFIG__` with the deployment mode, Home Assistant address, and supported display settings. The access token is kept on the backend and is never sent to the browser.

For example, a runtime config can look like:

```javascript
window.__ABBAI_FLOW_CONFIG__ = {
  deployment_mode: 'standalone',
  ha_url: 'http://homeassistant.local:8123',
  family_name: 'Sachs Family',
  theme: 'midnight',
  weather_entity: 'weather.home',
};
```

## Troubleshooting

If Home Assistant data is unavailable, check that `HA_URL` is reachable from the container and that `HA_TOKEN` is valid. After changing Docker environment variables, recreate or restart the container. Development `.env` changes require restarting the Vite server.
