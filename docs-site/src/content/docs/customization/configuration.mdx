# Configuration

Configure service connections after starting Abbai Flow in **Settings →
Integrations**. Enter the Home Assistant URL and token, Encore connection
details, Spotify developer app credentials, and the meal recipe/menu JSON feed
URL there. Configure Open-Meteo with a forecast URL that includes your
latitude and longitude; it is the default weather source and backup. You can
also configure a custom weather JSON API with an optional query or Bearer key
and JSON paths that map its current, daily, and hourly response fields. Meal
feeds can use an optional bearer token and configurable JSON paths to map a
provider's response to recipe fields. The app verifies the Home Assistant
connection before saving. Secrets are stored by the server in the persistent
data directory and are never returned to the browser.

Family name, theme, photos, and display behavior are also
editable in their existing Settings sections. New installations do not need
integration or family-preference variables in Docker Compose.

## Docker Compose

```yaml
services:
  abbai-flow:
    image: ghcr.io/nyabb/abbai-flow:latest
    ports: ['3000:3000']
    volumes:
      - abbai-flow-data:/data

volumes:
  abbai-flow-data:
```

The `/data` volume keeps family data and server-side integration credentials
across container restarts.

For meal feeds, set the path to the response's recipe array, then map each
recipe's title and steps plus any available ID, photo, ingredients, tags, date,
and source URL fields. Paths support dotted properties, array indexes, and
`[]` expansion (for example `$.data.recipes` or `$.instructions[].text`).

## Deployment environment variables

These values configure the server or its host environment and stay outside the
app UI:

| Variable                            | Purpose                                                                       | Default     |
| ----------------------------------- | ----------------------------------------------------------------------------- | ----------- |
| `ABBAI_FLOW_PORT` or `PORT`         | HTTP server port                                                              | `3000`      |
| `ABBAI_FLOW_DATA`                   | Directory for persisted data and integration credentials                      | `/data`     |
| `ABBAI_FLOW_DIST`                   | Built frontend directory                                                      | `/app/dist` |
| `ABBAI_FLOW_ALLOWED_ORIGINS`        | Additional allowed origins for state-changing requests                        | unset       |
| `ABBAI_FLOW_HA_CA`                  | Optional CA certificate for a private Home Assistant TLS certificate          | unset       |
| `ABBAI_FLOW_BLUETOOTH_DBUS_ADDRESS` | Host D-Bus socket address; the socket must also be mounted into the container | unset       |

Older family and display preference variables (`FAMILY_NAME`, `THEME`,
`PHOTO_DIRECTORY`, `PHOTO_INTERVAL`, and
`SCREEN_SAVER_TIMEOUT`) are initial defaults only. Set their current values in
the app.

## Local development

Run `npm ci` and `npm run dev`. Enter Home Assistant credentials in onboarding
or **Settings → Integrations**. For browser-based local development, Home
Assistant must allow requests from the development origin. `VITE_APP_VERSION`
is an optional build label.

## Runtime configuration

The server serves `/runtime-config.js` before the app loads. It identifies the
server-backed proxy and provides non-secret defaults such as the Home Assistant
URL. The access token and other integration secrets stay on the server.

```javascript
window.__ABBAI_FLOW_CONFIG__ = {
  deployment_mode: 'standalone',
  ha_url: 'http://homeassistant.local:8123',
};
```

## Troubleshooting

Use **Settings → Integrations → Test connection** to check the Home Assistant
URL and token. A failed test leaves the current configuration unchanged. For a
private TLS certificate, configure `ABBAI_FLOW_HA_CA` on the server. After
changing deployment-level variables, restart the container; app credentials
and preferences are edited in Settings without rebuilding the image.
